# Skill: @nativewindow/webview

Use this skill when working on the **native webview package** (`packages/webview`). This package provides native OS windows with embedded webviews for Bun/Node.js, built with Rust + napi-rs.

## Package Identity

- **npm name:** `@nativewindow/webview`
- **Location:** `packages/webview/`
- **Language:** Rust (native addon) + TypeScript (entry point)
- **Build tool:** napi-rs

## Architecture

### Command Queue Pattern

All window operations are **asynchronous via a command queue**. JS calls enqueue `Command` enum variants into the `WindowManager`. The `pumpEvents()` function drains and executes them on the main thread, then pumps the OS event loop.

```
JS call (e.g. win.loadUrl()) → Command::LoadURL enqueued → pumpEvents() executes on main thread
```

### Thread Safety

- Global mutable state uses `thread_local!` with `RefCell`.
- Access the manager via `with_manager(|mgr| { ... })`.
- Use `try_borrow()` with deferred processing for reentrant access.
- Separate thread-local maps (`TRUSTED_ORIGINS_MAP`, `ALLOWED_HOSTS_MAP`, `PERMISSIONS_MAP`) exist so platform delegates can read them while `MANAGER` is mutably borrowed.

### Event Pump Lifecycle

1. First `new NativeWindow()` auto-initializes the native subsystem and starts a `setInterval` pump (~16ms).
2. `pumpEvents()` drains commands, processes them, pumps OS events, then flushes deferred callback buffers.
3. When the last window closes, the pump stops automatically.

### macOS Event Drain (Phase B)

After tao's `run_return` (Phase A), `drain_macos_events` processes pending CFRunLoop sources and NSApp events needed for WebKit rendering. **Critical constraints:**

- **User input events (mouse/keyboard) must be excluded from the drain mask.** If a close-button click is dispatched via `sendEvent:` outside `run_return`, tao's `windowShouldClose:` delegate fires without an active event handler — the `CloseRequested` event is lost and the window never closes. The drain uses `NSEventMask::Any - user_input` to filter these out; they remain in the queue for the next `run_return`.
- **The drain has a safety cap** (`MAX_DRAIN_ITERATIONS = 500`) to prevent unbounded looping from cascading sources.

### Window Close Flow

OS-initiated close (X button) and programmatic `win.close()` follow different paths that converge at the same destruction logic:

- **`win.close()`** → sets `self.closed = true` → `Command::Close` → `destroy_window_entry()` during command processing → pushes to `PENDING_CLOSES`.
- **X button** → tao fires `CloseRequested` during `run_return` → pushes to `PENDING_CLOSES` → `destroy_pending_closes()` calls `destroy_window_entry()` after `pump_events()`.

**Key constraints for the close path:**

1. **`destroy_pending_closes` must not hold a `RefCell` borrow on `PENDING_CLOSES` while dropping windows.** The macOS Window drop triggers synchronous delegate callbacks that can route back through thread-local buffers. Collect IDs into a local `Vec` first, release the borrow, then destroy.
2. **`destroy_window_entry` hides the window before dropping** (`set_visible(false)` → `[NSWindow orderOut:]`) to ensure immediate visual removal.
3. **Dock visibility (`update_dock_visibility`) must run after `destroy_pending_closes`**, not inside `pump_events()`. OS-initiated closes are only destroyed by `destroy_pending_closes`, so the windows map is not yet empty when `pump_events` returns.

## File Structure

```
packages/webview/
  src/
    lib.rs              # Module entry: pumpEvents(), loadHtmlOrigin(), sanitizeForJs()
    window.rs           # NativeWindow class (#[napi]) — all public window methods
    window_manager.rs   # Global state, Command enum, command queue, thread-locals
    options.rs          # WindowOptions struct (#[napi(object)]) + CookieInfo
    events.rs           # Event callback type aliases (ThreadsafeFunction)
    security.rs         # Pure functions: json_escape, extract_origin, host matching, URL scheme validation
    pump.rs             # Event pump start/stop via setInterval
    runtime.rs          # checkRuntime(), ensureRuntime()
    platform/
      mod.rs            # Platform trait + cfg dispatch
      unified.rs        # Cross-platform implementation (tao + wry)
  index.ts              # TS entry point: native loader, type definitions, re-exports
  index.d.ts            # TS type declarations (auto-generated by napi-rs)
```

## Adding a New Window Method — Checklist

1. **Add command variant** in `src/window_manager.rs` (`Command` enum).
2. **Add `#[napi]` method** in `src/window.rs` — call `self.ensure_open()?` first, then enqueue the command via `with_manager`.
3. **Implement in platform** in `src/platform/unified.rs` — handle the new command in `process_command()`.
4. **Update `index.d.ts`** with the TypeScript type declaration.
5. **Update `index.ts`** — add the method to the `NativeWindowInstance` interface.

## Adding a New Event — Checklist

1. **Add callback type alias** in `src/events.rs` (e.g. `pub type FooCallback = FatalTsfn<String>;`).
2. **Add field** to `WindowEventHandlers` struct in `src/events.rs`, and initialize to `None` in `new()`.
3. **Add `#[napi]` handler registration** method in `src/window.rs` with `#[napi(ts_args_type = "...")]`.
4. **Add pending buffer** in `src/window_manager.rs` (e.g. `PENDING_FOO`).
5. **Flush the buffer** in `lib.rs` → `flush_pending_callbacks()`.
6. **Update `index.d.ts`** and `index.ts`.

## Rust Code Patterns

### napi Annotations

```rust
#[napi(constructor)]         // → new()
#[napi(getter)]              // → get property
#[napi(object)]              // → JS object mapping
#[napi(ts_args_type = "callback: (x: number) => void")]  // explicit TS callback type
```

### Error Handling

```rust
// All #[napi] functions return napi::Result<()>
self.ensure_open()?;  // Guard against closed windows
napi::Error::from_reason("descriptive message")  // Create errors
.ok_or_else(|| napi::Error::from_reason("..."))  // Option → Result
let _ = sender.send(());  // Explicitly discard results
```

### Command Enqueue Pattern

```rust
#[napi]
pub fn some_method(&self, arg: String) -> Result<()> {
    self.ensure_open()?;
    with_manager(|mgr| {
        mgr.push_command(Command::SomeCommand { id: self.id, arg });
    });
    Ok(())
}
```

## Security Features

- **URL scheme allowlist:** Only `http:`, `https:`, and `nativewindow:` schemes in `loadUrl()`.
- **Trusted origins:** Per-window IPC origin filtering via `trustedOrigins`.
- **Allowed hosts:** Navigation restriction via `allowedHosts` with wildcard support.
- **CSP injection:** Content Security Policy via `<meta>` tag.
- **JSON escape:** `sanitizeForJs()` / `json_escape()` for safe JS string embedding.
- **Permission flags:** Camera, microphone, file system access control.
- **Incognito mode:** Isolated, non-persistent sessions.
